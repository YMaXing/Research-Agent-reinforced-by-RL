<s slug="colpali-efficient-document-retrieval-with-vision-language-mo" type="golden_web">ColPali adapts Vision Language Models for page-level document retrieval by embedding document page images directly into multi-vector representations, paired with ColBERT-style late interaction for matching. The method skips PDF parsing, OCR, layout detection, and captioning pipelines. It builds on PaliGemma-3B, adding a projection layer that maps output token embeddings (image patches and text) to a 128-dimensional space, then applies the late interaction operator LI(q,d) = sum over query vectors of max dot-product with document vectors. Training uses an in-batch contrastive loss derived from pairwise cross-entropy on positive and hardest-negative scores, with LoRA adapters (r=32, α=32), bfloat16, paged_adamw_8bit, learning rate 5e-5, batch size 32, and one epoch; queries are augmented with five &lt;unused0&gt; tokens. The ViDoRe benchmark evaluates page-level retrieval across academic VQA repurposed tasks (DocVQA, InfoVQA, TAT-DQA, arXivQA, TabFQuAD) and practical industrial tasks (Energy, Artificial Intelligence, Healthcare Industry, Government Reports, Shift) spanning English and French, text, tables, figures, and infographics. It supplies 1,000 candidate pages and 100 queries per topic, generated via Claude-3 Sonnet and human-filtered, plus a training set of 118,695 query-page pairs (63% academic, 37% synthetic). Evaluation uses nDCG@5 as primary metric alongside Recall@K and MRR, plus query latency and indexing throughput. Baselines include Unstructured (with by-title chunking, optional OCR or Claude-3 Sonnet captioning) paired with BM25 or BGE-M3, plus contrastive VLMs (Jina CLIP, Nomic Embed Vision, SigLIP-So400m/14). ColPali achieves the highest nDCG@5 on all ViDoRe tasks, with largest gains on InfographicVQA, arXivQA, and TabFQuAD; it also exceeds Unstructured+captioning overall. Variants show BiSigLIP improves over SigLIP, BiPali adds multilingual gains via Gemma-2B, and ColPali’s multi-vector late interaction yields the decisive lift. ColQwen2-VL (768 patches) further improves +5.3 nDCG@5 over ColPali. Negative results include ColSigLIP and BiSigLIPPaliGemma variants performing below their single-vector counterparts. Indexing latency drops sharply because ColPali encodes pages in a single forward pass (NVIDIA L4, batch size 4); Unstructured+captioning requires layout, OCR, and captioning steps. Query encoding takes ~30 ms (batch size 1) versus 22 ms for BGE-M3; late interaction adds ~1 ms per 1,000 pages. Storage is 257.5 KB per page at D=128. Hierarchical mean token pooling (factor 3) reduces vectors 66.7% while retaining 97.8% performance on most tasks. The source includes tables detailing ViDoRe dataset statistics (language, queries, documents), full nDCG@5 and Recall@1 results across all tasks and models, training-split sizes, embedding sizes, and per-operation indexing latencies; it also provides similarity-map visualizations and prompt examples for caption generation. Limitations noted are performance degradation with fewer patches (512) or smaller language backbones, minor gains or drops when unfreezing the vision encoder, and a –2.2 nDCG@5 drop when training solely on DocMatix instead of the mixed set. No explicit handling of multi-page documents or dynamic corpus updates is described.</s>

<s slug="understanding-multimodal-llms" type="golden_web">Multimodal LLMs process multiple input modalities (primarily image + text) and output text. The source explains two core architectures. Method A (Unified Embedding Decoder Architecture) encodes images via a vision transformer (typically CLIP or OpenCLIP) into patches, applies linear projection or an MLP projector (sometimes called adapter/connector) to match text embedding dimensions, then concatenates image and text tokens for input to an unmodified decoder-only LLM (e.g., GPT-2, Llama, Qwen2). Variants such as Fuyu feed raw patches directly into a linear layer without a separate encoder. Method B (Cross-Modality Attention Architecture) keeps the same image encoder but injects image features via cross-attention layers inside the LLM transformer blocks, leaving the original self-attention intact. Training follows two stages after starting from a pretrained text-only LLM: (1) pretraining that typically freezes the LLM and image encoder while updating only the projector; (2) instruction and preference finetuning that often unfreezes the LLM. In Method B, cross-attention layers remain trainable throughout. Image encoders are commonly frozen (CLIP, SigLIP, InternViT-6B); exceptions include Llama 3.2, which trains a from-scratch ViT-H/14 on 2.5 billion image-text pairs while freezing the LLM to preserve text-only performance. Qwen2-VL uses 2D-RoPE and removes absolute position embeddings for native-resolution handling via “Naive Dynamic Resolution.” Pixtral trains a 400 M-parameter vision encoder from scratch and supports variable image sizes. NVLM compares three variants on the same Qwen2-72B-Instruct backbone: NVLM-D (decoder-only), NVLM-X (cross-attention), and hybrid NVLM-H (thumbnail + dynamic patches via cross-attention). Concrete models covered include Llama 3.2 (11 B and 90 B, cross-attention every fourth block, 224×224 inputs, 14×14 patches), Molmo (CLIP encoder + connector; backbones OLMo-7B, OLMoE-1B-7B, Qwen2-7B/72B; trains all parameters jointly), NVLM (InternViT-6B frozen, MLP projector), Qwen2-VL (675 M vision encoder, three-stage training), Pixtral 12B (Mistral NeMo backbone), MM1.5 (1 B–30 B, coordinate tokens for bounding boxes, ablation studies on data mixtures), Aria (24.9 B MoE, SigLIP 438 M, cross-attention), Baichuan-Omni (7 B, SigLIP + AnyRes, three-stage projector/vision/LLM training), Emu3 (Llama-2-style decoder trained from scratch with VQ tokenizer and DPO for image generation), and Janus (DeepSeek-LLM 1.3 B, decoupled SigLIP understanding encoder + VQ generation encoder, three-stage training). The source includes a 23-line PyTorch PatchProjectionLayer example and equivalent Conv2d implementation for patch embedding. It notes that Method A is simpler to implement while Method B offers better efficiency on high-resolution inputs and preserves text-only capability when the LLM stays frozen. The article deliberately omits systematic benchmark tables and historical coverage, citing data contamination and architectural heterogeneity that prevent clean apples-to-apples comparisons; only NVLM supplies a controlled three-way comparison.</s>
<s slug="vision-language-models" type="golden_web">Vision Language Models (VLMs) are multimodal generative AI systems that combine a large language model (LLM) with a vision encoder to process and reason over interleaved video, image, and text inputs, producing text outputs. Unlike fixed-class CNN-based computer vision models, VLMs support open-ended natural language instructions for tasks including visual question-answering, classification, optical character recognition, image/video summarization, document parsing, and multi-image comparison. Core architecture consists of three components: a CLIP-based transformer vision encoder trained on image-text pairs, a projector (linear layer in LLaVA and VILA; cross-attention layers in Llama 3.2 Vision) that maps encoder outputs to LLM-compatible image tokens, and any off-the-shelf LLM. Training proceeds in stages—pretraining on image-caption and interleaved image-text corpora for alignment, followed by supervised fine-tuning on prompt-response pairs, with optional parameter-efficient fine-tuning (PEFT) for domain adaptation. Deployment typically uses an OpenAI-style REST API. The source includes a use-cases diagram, a three-part architecture diagram, a multi-stage training-process diagram, an MMMU benchmark multiple-choice example, and a real-world video analytics diagram. It lists research directions such as ensembling vision encoders, tiling high-resolution inputs, and extending context length (citing LongVILA arXiv:2408.10188 and arXiv:2408.15998). Benchmarks covered are MMMU, Video-MME, MathVista, ChartQA, and DocVQA, which evaluate perception, knowledge, and reasoning via multiple-choice and numerical questions drawn from academic sources. Concrete NVIDIA offerings include NVIDIA Cosmos Reason (7B-parameter reasoning VLM), NVIDIA NIM microservices with VLM inference endpoints, Metropolis Video Search and Summarization (VSS) Blueprint integrating VLMs, LLMs, and RAG, and reference workflows at github.com/NVIDIA/metropolis-nim-workflows. Real-world claims cite Pegatron’s deployment yielding a 7% reduction in labor costs per assembly line and 67% decrease in defect rates, and Linker Vision’s processing of thousands of live streams for incident detection. Limitations explicitly noted are restricted spatial understanding from CLIP encoders (typical 336×336 or 448×448 input resolution), difficulty with small objects or precise localization, and constrained context length for long-video understanding; mitigations under exploration include tiling and higher-resolution encoders.</s>
<s slug="YOvxh_ma5qE" type="golden_youtube">Multimodal embeddings align representations across data modalities such as text and images in a shared vector space, enabling tasks like zero-shot image classification and image search. The video centers on CLIP, while noting the approach generalizes beyond text-image pairs. Embeddings are defined as semantically meaningful numerical representations learned via training, illustrated first with BERT’s masked language modeling: input sequences yield token-level matrices (n x d) that are averaged to sequence-level 1 x d vectors after dropping the classification head. Separate unimodal spaces (text vs. image) are shown to be unaligned; multimodal embeddings merge them so that matching concepts cluster together. Creation relies on contrastive learning using positive pairs (image + matching caption) and negative pairs (image + mismatched caption). Raw embeddings from any image or text encoder are projected via learnable weight matrices W_I and W_T, L2-normalized, and assembled into matrices I_e and T_e (both n x d). A logits matrix is formed as logits_i,j = sim(I_e[i], T_e[j]) / τ (cosine similarity, temperature τ). Contrastive loss is computed separately for images (L_I) and text (L_T) by maximizing diagonal (positive) entries and minimizing off-diagonal entries via the formulation L = (L_I + L_T)/2, exactly as derived in the CLIP paper. <s slug="what-is-optical-character-recognition-ocr" type="exploitation">Optical Character Recognition (OCR) converts handwritten and typed text from images, videos, and scanned documents such as PDFs into machine-readable, editable, and searchable digital formats. The standard pipeline comprises five stages: image pre-processing (resizing, contrast enhancement, binarization, noise reduction); text detection via deep-learning models trained on image-text datasets; optional layout analysis to preserve text structure and reading order; text recognition using CNN-RNN combinations to output characters and words; and language-model post-processing (statistical or deep-learning) for spelling correction and sequence probability refinement.
